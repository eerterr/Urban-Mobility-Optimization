# Краткий обзор подходов

Цель обзора — выбрать практичный способ прогноза **числа отправлений со станции через час** на доступных данных Divvy. Это не прогноз наличия велосипедов: без инвентаря и неудовлетворённого спроса число наблюдаемых поездок остаётся лишь приближением спроса.

| Источник | Подход | Решение для этого проекта |
| --- | --- | --- |
| [scikit-learn: lagged features](https://scikit-learn.org/stable/auto_examples/applications/plot_time_series_lagged_features.html) | Табличный прогноз через лаги, временные splits вместо случайного деления | Лаги 1–169 часов, три expanding-window folds, декабрьский holdout |
| [scikit-learn: cyclical features](https://scikit-learn.org/stable/auto_examples/applications/plot_cyclical_feature_engineering.html) | Периодические признаки времени и временная проверка | Синус и косинус часа, дня недели и месяца; календарные значения также сохранены |
| [Divvy rebalancing, GitHub](https://github.com/rishi-kumar0208/divvy-bike-rebalancing) | Станции добавляются после первого наблюдения; признаки используют только прошлое; LightGBM получает категориальный ID | Аналогичная логика начала панели и сдвига лагов; CatBoost получает ID станции как категорию |
| [LightGBM documentation](https://lightgbm.readthedocs.io/en/latest/Features.html) | Гистограммный бустинг ускоряет обучение на больших таблицах | Сравнение с HistGradientBoosting и ограничение числа обучающих строк вместо полного Grid Search |
| [Feng et al., ACM TKDD 2024](https://doi.org/10.1145/3690388) | Спрос неоднороден по месту и времени; активность может концентрироваться на отдельных станциях | Отдельные метрики для активных станций и часов пик; нейросеть на графе не нужна без проверенного выигрыша над табличным baseline |
| [Liu et al., IEEE Access 2024](https://ieeexplore.ieee.org/abstract/document/10756689) | Моделирование пространственных связей и сезонного поведения на уровне станций | Сезонные окна validation и станционная идентичность; пространственные графы остаются возможным дальнейшим исследованием |

## Вывод для эксперимента

Базовый уровень должен включать предыдущий час, аналогичный час предыдущего дня и предыдущей недели. Обычная случайная выборка для train/test завысила бы оценку из-за автокорреляции. Для вычислительной эффективности параметры подбираются на 400 тыс. исторических строк и одном июльском периоде; в каждом последующем fold модель обучается на выборке до 800 тыс. строк из доступного **прошлого** и оценивается на всех строках validation. Сравнение CatBoost и HistGradientBoosting проверяет, окупается ли использование идентичности станции. При качестве в пределах 1% от лучшего CV-результата выбирается более быстрая модель. Окончательный выбор делается до просмотра декабрьской метрики.

## Что может улучшить следующий этап

1. Официальный реестр работающих станций вместо 30-дневной эвристики активности.
2. Прогноз погоды или историческая погода, если источник и временная доступность признаков надёжно задокументированы.
3. Прогноз прибытий и данные об инвентаре для реальной задачи ребалансировки.
4. Проверка полного обучения против ограниченной выборки при наличии достаточных RAM и времени; сейчас лимит строк явно зафиксирован в отчёте.
